Graphic file

A graphic file (<name>.graphic.json, in a question folder) keeps initdata, start state, decimal separator and [[jsxgraph]] block, without making a question or a test case of it. The list shows the graphic files of all question folders.

initdata

JSON list of meclib objects, i.e. what stackjson_stringify(initdata) produces. A leading initdata: and a trailing ; or $ are ignored, so a constant Maxima list can be pasted as is.

Start state (objects input)

If filled, meclib starts from this state instead of initdata, as when a student revisits an answered question. Use "Use as start state" below to continue from the current graphic.

STACK [[jsxgraph]] block

As in the question text. {#init#} is replaced by initdata, {#stackfltsep#} by the decimal separator, and the [[include ...meclib.js"/]] line by the meclib.js version selected above. Width, height and input-ref-... are taken from the opening tag. Presets from the wiki page "MecLib Question Setup":

Save as question

Writes a new Moodle XML file with a meclib question from the template: initdata in the question variables, the [[jsxgraph]] block above in the question text, the inputs objects and names. "..." chooses another folder (it is added to the question folders). Continue on the Questions page.

Save as test case

Saves the current graphic as a case: its state (the current objects if you have interacted with the graphic, otherwise the start state, if any) is rendered once more, and the resulting objects and names are stored as the expected result. All cases of a scene share the same initdata, decimal separator and [[jsxgraph]] block. The case id is how Maxima tests refer to the case: scene_obj("scene", "id"), scene_names("scene", "id").
